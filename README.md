# 成都地铁通勤压力可视化分析

数据分析可视化课程作业。用在线抓取的成都地铁线网，看站点分布、换乘衔接和站间距过大的区段。

## 选题背景

成都地铁已覆盖中心城区、天府新区、双流机场和部分市域方向，日常通勤高度依赖轨道交通。线网里程增长之后，乘客感受到的差异往往不在“有没有地铁”，而在“车站离居住地有多远、要不要换乘、市域线路站距是不是很大”。

公开渠道很少提供可复现的客流和满载率。课程项目改从线网开放数据入手：车站在哪里、一条线有多少站、相邻站相距多远、哪些站衔接了多条线。这些指标不能代替客流，但能说明通勤在空间上哪里更方便、哪里更依赖步行或公交接驳。

## 要解决的社会问题

问题是：**地铁成网之后，通勤覆盖并不均匀。**

- 核心区换乘站密集，早晚高峰的压力首先出现在衔接，而不是单纯“有没有站”。
- 市域和机场方向站间距明显拉大。住在两站之间的人，走到车站的时间更长，地铁对这部分居住地的覆盖更弱。
- 讨论新线是否方便通勤时，需要一张能筛选线路、能量出站间距的图，而不是只看线路图上的站名。

本项目把“覆盖缺口”定义成可调节的站间距阈值（默认 2 公里），把“衔接压力”定义成换乘站衔接的线路数。演示时可以改阈值，比较核心区和市域快线。

## 数据源

爬虫 `spider.py` 按下面的顺序联网获取，不会在代码里写死站点坐标。

1. **TransitFeeds（OpenMobilityData）**  
   请求 `https://api.transitfeeds.com/v1/getFeeds`，查找成都相关 GTFS 压缩包。该站已于 2025 年 12 月停止更新，接口经常返回 401/403，脚本会捕获超时和 HTTP 错误后继续。

2. **Mobility Database 目录**  
   TransitFeeds 的后续目录：`https://files.mobilitydatabase.org/feeds_v2.csv`。若其中出现成都 GTFS 的 zip 地址，则下载并解析 `stops.txt`、`routes.txt`、`trips.txt`、`stop_times.txt`。当前这份全球目录没有成都地铁记录。

3. **高德地图公开地铁线网（目录中没有成都 GTFS 时的回退）**  
   先请求城市列表 `citylist.json`，取出“成都市”的行政区划代码和拼音，再请求对应的线网 JSON。返回结果包含线路、站序和 GCJ-02 坐标。脚本把坐标转换成地图底图使用的 WGS84，并整理成与 GTFS 对应的 CSV。

导出文件在 `data/`：

| 文件 | 内容 |
| --- | --- |
| `stops.csv` | 站点、坐标、所属线路、是否换乘 |
| `routes.csv` | 线路名称、颜色、站点数 |
| `stop_times.csv` | 每条线路上下行的停站顺序 |
| `segments.csv` | 相邻站及球面距离（米） |
| `feed_info.csv` | 本次实际使用的来源 URL 和抓取时间 |

这些表描述线网结构，不含客流、限流和满载率。

## 运行步骤

需要 Python 3.10 及以上。在项目目录打开 PowerShell：

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python spider.py
streamlit run app.py
```

浏览器打开终端里给出的本地地址（一般是 http://localhost:8501）。

页面可以：

- 在侧边栏勾选线路；
- 查看站点数、换乘站、平均站间距和超距段数量；
- 在地图上区分普通站和换乘站，红色线段表示超过阈值的区间；
- 调整“覆盖缺口阈值”，查看缺口明细和核心区 / 近郊 / 远郊的站点分布。

若课堂网络不能访问数据源，只要 `data/` 里已有上次抓取的 CSV，仍可直接运行 `streamlit run app.py`。需要更新线网时再执行 `python spider.py`。

## 项目价值

- 把“通勤不方便”落成可计算的站间距和换乘结构，演示时能指出具体是哪两个站之间过远。
- 数据来自当次网络请求，抓取时间写在 `feed_info.csv`，方便说明数据不是手工抄录的静态表。
- 页面只依赖 Streamlit 和本地 CSV，不需要地图密钥，适合投影演示。
- 明确写出指标边界：这是覆盖与衔接分析，不能当成客流或拥挤度结论。
